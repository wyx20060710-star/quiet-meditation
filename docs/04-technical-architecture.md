# 极简冥想计时器：技术架构与数据约定

> 版本：1.0.0  
> 阶段：4 — 技术架构  
> 日期：2026-08-04  
> 上游约束：`PROJECT_CHARTER.md`、`01-ux-spec.md`、`02-visual-system.md`、`03-motion-spec.md`  
> 机器可读数据契约：`04-data-contracts.schema.json`

## 1. 交付结论

阶段 4 固化以下实现选择：

- 应用采用 **TypeScript + Vite + 原生 DOM／SVG／CSS**，不引入 UI 框架、业务后端、账号或远程数据库；
- 三个主要页面是同一文档内的三个视图，不创建第四页面；
- 计时领域状态机是唯一业务真值，页面、ARIA、动效、声音与 PWA 都是状态消费者；
- 当前文档存活时以单调时钟计算有效时长，跨刷新／关闭恢复以持久化墙钟锚点续算；
- 计时状态、日汇总和结算回执存入原生 IndexedDB，并在一个读写事务中完成单次结算；
- 同一时间只允许一个活动会话。双击、多标签页、自然完成与提前结束竞争时，只有一个事务可以成为结算赢家；
- 最近 7 天和 15 天数据全部由最近 15 个本地自然日的日汇总派生，不保存逐次会话历史；
- 恢复、时钟异常、数据损坏和存储不可用均有确定降级路径，不猜测时长、不阻断当前页面核心操作；
- 阶段 5 只实现三页、计时、记录和统计；主题、声音、完整恢复、离线与 PWA 的增强实现仍按总纲留在阶段 6，但接口在本阶段固定。

这套架构以准确结算和可恢复性为首要目标，同时维持很小的运行时表面积。

## 3. 架构驱动因素

优先级按总纲保持：安静感、操作清晰、计时可靠、可访问性、视觉表现、功能丰富。

技术上必须守住六条不变量：

1. `remaining` 只能由时间模型计算，不能由 `setInterval` 次数或 SVG 动画计算；
2. 一个会话最多产生一次结算回执、一次日汇总增量和一次完成音尝试；
3. 暂停与确认期间的墙钟时间不计入实际时长；
4. 领域状态先改变，DOM、ARIA 和动效随后呈现；动效取消不改变结果；
5. 任何不可验证的活动会话都不得生成猜测性记录；
6. 记录只保留最近 15 个本地自然日，缺失日期由查询层补零。

## 4. 正式技术选型

| 层 | 选择 | 约束理由 |
|---|---|---|
| 语言 | TypeScript，严格模式 | 让状态和持久化数据的非法组合在开发期可见 |
| 构建 | Vite + `tsc --noEmit` | Vite 产出静态资源；独立 TypeScript 检查作为构建门禁 |
| 视图 | 原生 DOM 模板、语义 HTML、SVG、CSS | 三页规模不需要 UI 框架；减少运行时和状态副本 |
| 领域状态 | 纯 reducer + effect runner | 状态转换可穷举测试，副作用不能反向成为真值 |
| 存储 | 原生 IndexedDB | 支持跨对象存储的原子读写事务和多标签页写入串行化 |
| 标签页同步 | `BroadcastChannel`；不可用时依靠可见性恢复重读 | 广播只负责通知，IndexedDB 始终是最终真值 |
| 当前文档计时 | `performance.now()` | 单调递增，不受当前文档内墙钟调整直接影响 |
| 跨文档恢复 | `Date.now()` 持久化锚点 + 完整性检查 | 浏览器关闭后没有可持久化的单调时钟，必须有明确降级 |
| 单元测试 | Vitest | 测试纯状态机、日期、统计和故障分支 |
| 浏览器测试 | Playwright | 验证真实 IndexedDB、刷新、后台、焦点、ARIA 和多页面竞争 |

依赖使用规则：生产运行时不引入状态库、日期库、图表库或 IndexedDB 封装库。Vite 只负责转译和打包，`typecheck` 必须单独执行 `tsc --noEmit`。图表使用语义 HTML／SVG；日期只做本地日历运算；PWA 构建工具属于阶段 6 的开发期适配器，不进入领域层。

## 5. 总体结构

```text
用户输入／浏览器生命周期／时钟采样
                    │
                    ▼
          应用协调器 App Controller
                    │ dispatch(event)
                    ▼
         纯领域状态机 Timer Reducer
          │         │          │
          │         │          └── Effect 描述
          │         └── 派生选择器
          └── 唯一 AppState
                    │
       ┌────────────┼─────────────┐
       ▼            ▼             ▼
 DOM + ARIA     Motion Adapter   Effect Runner
                                   │
                       ┌───────────┼───────────┐
                       ▼           ▼           ▼
                    Clock      IndexedDB     Sound
                                   │
                             BroadcastChannel

PWA／Service Worker 只缓存静态资源，不读写或驱动领域状态。
```

每个箭头都是单向的。视图不得直接写 IndexedDB，存储回调不得直接操作 DOM，CSS 动画事件不得触发暂停或结算。

## 7. 状态模型

### 7.1 领域状态与页面状态分离

领域状态：

```ts
type TimerState =
  | { tag: 'idle' }
  | { tag: 'running'; session: RunningSession }
  | { tag: 'paused'; session: FrozenSession }
  | { tag: 'confirming'; session: FrozenSession; resumeTo: 'running' | 'paused' }
  | { tag: 'settling'; sessionId: string; reason: 'natural' | 'early' }
  | { tag: 'completed'; receipt: SettlementReceipt };
```

页面呈现状态：

```ts
type ViewState = {
  route: 'boot' | 'home' | 'timer' | 'completion';
  controls: 'hidden' | 'visible';
  records: 'collapsed' | 'expanded';
  reducedMotion: boolean;
};
```

以下组合非法并必须在 reducer 或选择器边界被拒绝：

- `idle`、`settling` 或 `completed` 显示进行页可操作控制；
- `paused` 或 `confirming` 的关键控制为隐藏；
- `completed` 仍保留同 ID 的活动会话；
- `running` 没有持久化锚点；
- `paused`／`confirming` 仍有活动运行锚点；
- `completion` 没有合法结算回执；
- `home` 展示未解决的合法活动会话。

### 7.2 事件与转换

| 当前领域状态 | 事件 | 下一状态 | 原子副作用／说明 |
|---|---|---|---|
| `idle` | `START(minutes)` | `running` | 事务检查无活动会话后创建唯一 ID |
| `running` | `TICK(sample)` | `running` | 只更新内存派生显示；不逐秒写库 |
| `running` | `PAUSE(sample)` | `paused` | 先冻结有效时长并持久化，再呈现暂停 |
| `paused` | `RESUME(sample)` | `running` | 用冻结累计值建立新锚点 |
| `running`／`paused` | `OPEN_END_CONFIRM(sample)` | `confirming` | 运行态先冻结；持久化 `resumeTo` |
| `confirming` | `CANCEL_END(sample)` | `running`／`paused` | 按 `resumeTo` 恢复，不由模态动画决定 |
| `confirming` | `CONFIRM_END(sample)` | `settling` | 0 秒走无记录结束；其余提交提前结算 |
| `running` | `TIME_REACHED_ZERO(sample)` | `settling` | 提交自然结算；多次事件共享同一会话 ID |
| `settling` | `SETTLED(receipt)` | `completed`／`idle` | 有记录进入完成页；0 秒回首页 |
| `completed` | `REPEAT` | `running` | 原计划分钟创建新 ID，事务防重复 |
| `completed` | `RETURN_HOME` | `idle` | 保留选择时长，记录不变 |

控制显隐和最近记录展开不进入计时领域状态。它们不能触发存储或结算。

### 7.3 同时事件优先级

同一任务队列或多个标签页中发生竞争时，按以下顺序确定结果：

1. 已存在的结算回执；
2. `actualRemainingMs <= 0` 的自然完成；
3. 用户已经激活的“结束并记录”；
4. 暂停／继续／打开确认；
5. 显隐、转场、声音和装饰动画。

最终胜负仍由 IndexedDB 事务中的会话 ID 和结算回执决定，而不是事件到达 UI 的先后。

## 8. 时间模型

### 8.1 单位与取整

- 配置和日汇总使用整数秒；
- 运行计算使用整数毫秒；
- 计划时长为 `minutes × 60_000`；
- 提前结束的实际秒数为 `floor(effectiveElapsedMs / 1000)`；
- 自然完成固定记录完整计划秒数；
- 进行页显示 `ceil(remainingMs / 1000)`，并钳制在 `0..plannedSeconds`；
- 0 秒提前结束写入无记录回执、清除活动会话并返回首页；1 秒起计一次完成。

使用 `ceil` 显示剩余时间可以避免刚开始就从 `20:00` 跳成 `19:59`；业务结算仍按毫秒真值计算。

### 8.2 运行锚点

运行会话保存：

- `accumulatedMs`：当前锚点之前已确认的有效时长；
- `anchorWallMs`：最近一次成功持久化锚点的 Unix 毫秒；
- 当前文档内的 `anchorMonoMs`：只保存在内存，来自 `performance.now()`；
- `plannedDurationSeconds`：固定计划秒数。

同一文档且处于可正常采样状态时：

```text
effectiveElapsedMs = accumulatedMs + max(0, nowMonoMs - anchorMonoMs)
remainingMs = clamp(plannedMs - effectiveElapsedMs, 0, plannedMs)
```

暂停或打开提前结束确认时，先计算 `effectiveElapsedMs`，将它写回 `accumulatedMs`，再移除运行锚点。因此确认阅读时间永不计入实际时长。

### 8.3 刷新、关闭与后台

进入后台、`pagehide`、暂停、确认、继续和结算前执行检查点。普通运行无需每秒持久化。

跨文档恢复没有可靠的单调时钟，使用：

```text
wallGapMs = nowWallMs - anchorWallMs
restoredElapsedMs = accumulatedMs + max(0, wallGapMs)
```

恢复后立刻建立新的墙钟和单调时钟锚点。若恢复结果归零，直接进入单次自然结算，不播放追赶动画。

后台／锁屏期间计时应继续。页面从隐藏恢复时，先用墙钟差校正后台时间，再建立新单调锚点；圆环直接落到真实进度，不播放补偿动画。

### 8.4 墙钟变化检测与限制

当前文档可比较墙钟差与单调时钟差：

```text
driftMs = (nowWallMs - anchorWallMs) - (nowMonoMs - anchorMonoMs)
```

- 页面持续可见且 `abs(driftMs) > 2_000` 时，判定墙钟发生跳变；本段只采用单调差，并用当前墙钟重新锚定；
- 墙钟倒退导致 `nowWallMs < anchorWallMs - 2_000` 时，跨文档恢复不可信，放弃活动会话且不写记录；
- 存储时间、计划时长、累计时长或锚点超出数据契约范围时，按损坏会话处理；
- 跨关闭期间发生的“真实等待”和“系统时钟同幅前跳”在无网络、无可信外部时钟的网页中不可区分。若墙钟向前且数据其余部分有效，产品按真实等待恢复／自然完成；不得宣称检测到无法证明的改时；
- 时区变化不改变已运行毫秒数，只影响结算瞬间生成的本地日期键。

这项不可区分性是纯本地网页的物理限制。安全边界是：不显示负数、不超过计划时长、不重复结算；明确可判定为倒退或损坏时不生成猜测记录。

## 9. 持久化模型

### 9.1 数据库

- 数据库名：`quiet-meditation`；
- 结构版本：`1`；
- 对象存储：`runtime`、`preferences`、`dailyRecords`、`settlements`；
- 所有读取均通过运行时验证器；TypeScript 类型不能替代持久化边界验证；
- 数据结构以 `04-data-contracts.schema.json` 为机器可读真值。

### 9.2 对象存储

| store | key | 内容 | 保留策略 |
|---|---|---|---|
| `runtime` | `activeSession` | 0 或 1 个活动会话 | 结算事务中删除 |
| `runtime` | `uiRuntime` | 选择分钟、最后完成回执 ID | 更新覆盖 |
| `preferences` | `user` | 主题、声音开关 | 更新覆盖；损坏则字段级默认 |
| `dailyRecords` | `YYYY-MM-DD` | 当日总秒数、完成次数 | 只留含当前本地日在内 15 天 |
| `settlements` | `sessionId` | 单次结算回执和完成页快照 | 最多保留最近 15 个本地日 |

不保存逐次会话明细列表。`settlements` 是幂等回执，不用于向用户展示历史会话；完成页只读取 `uiRuntime.lastCompletionId` 指向的一个快照。

### 9.3 活动会话

持久化会话状态只有：

- `running`：有 `accumulatedMs` 和墙钟检查点；
- `paused`：累计时长冻结；
- `confirming`：累计时长冻结，并保存 `resumeTo`。

会话 ID 使用 `crypto.randomUUID()`。计划分钟创建时固定，之后不可因首页选择变化或提前结束实际时长而修改。

### 9.4 日期与统计

日期键使用结算发生时设备本地日期的 `YYYY-MM-DD`，从本地年、月、日组件生成，不使用 `toISOString()` 截取 UTC 日期。

- 跨午夜只归入结算发生日，不拆分；
- 最近 N 天通过本地日历逐日递减生成，不使用 `N × 24h` 毫秒减法，避免夏令时边界错误；
- 已保存的日期键不因之后切换时区而重新分桶；
- 查询层固定生成含今日的 15 个日期，再左连接合法日汇总；
- 7 天统计取该序列最后 7 天；
- 15 天柱高以序列中的最大 `totalSeconds` 为分母；全零时只显示零基线；
- 任何无效日按 0 参与显示，并在下一次成功维护事务中清理或修复；
- 清理阈值使用本地日历日期，不使用记录写入时间。

## 10. 原子结算与幂等

### 10.1 事务范围

自然完成和提前结束共用一个 `settleSession(command)`。它在同一个 IndexedDB `readwrite` 事务中覆盖：

```text
runtime + dailyRecords + settlements
```

事务步骤：

1. 读取 `settlements[sessionId]`；存在则直接返回该回执，不增加日汇总；
2. 读取 `runtime.activeSession`；不存在或 ID 不同则拒绝为陈旧命令；
3. 验证会话与结算原因，并从时间模型得到受钳制的实际秒数；
4. 生成结算瞬间的本地日期键；
5. 若提前结束为 0 秒，不写日汇总，但写 `recorded: false` 回执；
6. 否则读取／创建当日日汇总，增加秒数和次数各一次；
7. 写入结算回执；
8. 删除活动会话，更新 `uiRuntime.lastCompletionId` 或为 0 秒清空它；
9. 裁剪 15 日外的日汇总和结算回执；
10. 等事务 `complete` 后才向状态机派发 `SETTLED`。

任一步失败都让事务整体回滚。不得先改内存统计再“尽力保存”，也不得分两个事务先写日汇总后写回执。

### 10.2 竞争保护

- 双击开始：创建活动会话事务先检查 `activeSession`；第二个请求返回已存在会话；
- 双击暂停／继续：事件携带期望状态和会话 ID；状态已变化时忽略；
- 自然完成与提前结束竞争：两个命令使用同一会话 ID；第一个事务写回执并删除活动会话，第二个读取回执后返回同一结果；
- 多标签页：IndexedDB 写事务串行化；事务提交后广播 `session-changed` 或 `settled`，其他标签页重新读取，不信任广播载荷；
- 旧页面回调：会话 ID 与当前活动会话不匹配时拒绝；
- 完成页后退：完成视图只读回执，不具有重新结算入口。

### 10.3 完成音一次性规则

声音不是结算事务的一部分。事务成功后，仅结算赢家所在的活跃文档可以发出一次 `PLAY_NATURAL_COMPLETION` effect，并同时在内存登记已尝试：

- 仅 `reason === natural`；
- 声音偏好开启；
- 文档当前可见且具备用户激活／播放条件；
- 本次结算由当前活跃流程即时完成，而不是启动恢复得到；
- 无论成功或失败都不重试，不阻断完成页；
- 其他标签页收到广播只更新页面，不播放声音。

结算回执保存 `soundDisposition`（`not-eligible`、`attempted` 或 `failed`）仅用于当前完成流程的幂等判断，不保存音频历史分析。

原子结算先将其写为 `not-eligible`，表示任何恢复流程都不得补播；当前结算赢家若立即尝试播放，再以独立、可失败的小事务更新为 `attempted` 或 `failed`。这个后续更新不改变结算、日汇总或页面去向。

## 11. 启动与恢复

启动阶段在任何主页面渲染前完成最小恢复判断，期间只显示中性静态占位，避免先闪现错误时间。

```text
打开数据库
  ├─ 失败 → 内存降级模式 → 首页
  └─ 成功
       ├─ 读取并字段级验证偏好、选择值
       ├─ 读取 lastCompletion 和 activeSession
       └─ activeSession?
            ├─ 否 → 合法 lastCompletion 且历史状态要求完成页？
            │        ├─ 是 → 完成页
            │        └─ 否 → 首页
            ├─ running → 恢复计算
            │        ├─ 剩余 > 0 → 进行页／控制隐藏
            │        ├─ 剩余 = 0 → 幂等自然结算 → 完成页
            │        └─ 不可信 → 删除活动会话 → 首页
            ├─ paused → 进行页／暂停，保持冻结值
            └─ confirming → 进行页／确认层，按 resumeTo 等待选择
```

恢复后的规则：

- 不补播完成音；
- 不播放进度追赶动画；
- 暂停不会自动继续；
- 确认层仍保持冻结与焦点语义；
- 合法活动会话优先于 URL／history state；
- 损坏活动会话被删除且不结算，合法偏好和日记录仍保留；
- 损坏日记录不影响活动会话恢复。

## 12. 路由与浏览器历史

应用只有一个 HTML 入口，不依赖服务器路径回退。路由使用同 URL 的 History API state 标识 `home`、`timer`、`completion`，但持久化领域状态拥有更高优先级。

- 首页开始：push `timer`；
- 进行页浏览器后退／PWA 返回：拦截为打开提前结束确认，不丢弃会话；取消后保持进行页；
- 成功结算：replace 当前 `timer` 为 `completion`，使后退不回到已结束计时器；
- 完成页返回首页：replace 为 `home`；
- 再次冥想：replace／push 为新的 `timer`，但只有新会话事务成功后生效；
- 最近记录展开只更新原页状态，不创建历史条目；
- 刷新时 URL 不决定是否存在会话，启动恢复负责校正。

历史事件只发领域事件，不能直接删除活动会话。

## 13. 视图、动效与可访问性

### 13.1 渲染原则

- 一个 `AppState` 产生可见 DOM、ARIA 状态和可用操作；
- 主体圆环容器与覆盖控制层分离，控制显隐不改变布局；
- 倒计时文本与进度值来自同一个 `remainingMs` 选择器；
- 每秒 tick 只更新时间文本和 SVG 进度变量，不重建整页；
- 读屏实时区域只在开始、暂停、继续、恢复和完成播报，不每秒播报；
- 隐藏控制在淡出开始时立刻 `inert` 并移出 Tab 顺序；
- 暂停和确认状态的继续入口始终可访问。

### 13.2 动效契约

`03-motion-tokens.json` 是动效参数真值。CSS 动效只消费稳定领域状态：

- 不监听 `animationend` 才写入暂停、完成或记录；
- 当前状态变化时可取消旧动画，最终 DOM 必须立即具备新状态语义；
- 后台恢复、大幅进度校正和启动恢复禁用进度补间；
- `prefers-reduced-motion: reduce` 取消呼吸、位移、柱形生长和进度补间；
- 4 秒控制时限来自 token，不因减少动态改变。

### 13.3 图表

15 日趋势由统计选择器输出固定 15 项。视觉层只接收日期、秒数、次数和相对比例，不自行求和。每根柱必须有等价文本；全零数据仍保留 15 个日期语义。

## 14. 偏好、声音、存储与 PWA 隔离

### 14.1 偏好

主题和声音偏好各自验证。一个字段损坏不能让整个偏好记录失效：

- 无主题时默认 `stone`；
- 无声音值时默认 `true`；
- 当前页面修改先更新内存，再异步持久化；保存失败只影响下次启动；
- 主题用根节点语义变量实现，领域状态不识别色值。

### 14.2 存储不可用

IndexedDB 打不开、事务持续失败或处于受限浏览模式时，应用进入当前文档的内存降级模式：

- 可以选择时长、开始、暂停、继续、提前结束和自然完成；
- 当前文档内仍防重复结算并显示完成结果；
- 不承诺刷新恢复和长期记录；首页／完成页统计按当前内存可证明的数据展示；
- 不显示阻断弹窗或循环重试；可以使用一条非侵入、可读屏的状态说明，但不得盖住开始按钮。

阶段 5 应以可注入存储接口测试此模式。

### 14.3 PWA

Service Worker 只负责同源静态资源缓存：

- 不拦截领域事件，不持有计时器，不结算会话；
- 不缓存用户 IndexedDB 数据；
- 更新失败、安装失败或离线缓存缺失时，普通网页核心流程不变；
- 新 Service Worker 激活不能清理 IndexedDB；
- 版本升级的数据迁移只由页面内数据库模块执行。

## 15. 数据验证、迁移与故障策略

### 15.1 读取验证

所有持久化对象依次检查：

1. 对象形状与 `schemaVersion`；
2. 枚举值；
3. 有限整数、范围和字段关系；
4. 日期键与 store key 一致；
5. 状态特有字段；
6. 跨记录引用，例如 `lastCompletionId` 是否存在。

### 15.2 损坏隔离

| 损坏对象 | 处理 |
|---|---|
| 偏好单字段 | 该字段回默认，其他字段保留 |
| 选择分钟 | 回 20 分钟 |
| 活动会话 | 删除活动会话，回首页，不结算 |
| 单日日汇总 | 该日按 0；其他合法日保留 |
| 结算回执 | 不用于完成页；若仍有同 ID 活动会话，只有活动会话完整时才可继续恢复 |
| `lastCompletionId` 悬空 | 清空引用，回首页或按活动会话恢复 |
| 数据库迁移失败 | 中止升级并进入内存降级；不循环删除数据库 |

不得因为一条坏日记录删除全部 15 天数据，也不得因为偏好损坏删除活动会话。

### 15.3 迁移

- IndexedDB 结构版本和记录 `schemaVersion` 分开管理；
- 升级函数按版本逐级、幂等执行；
- 无法证明安全的活动会话字段不做猜测迁移，丢弃该活动会话；
- 日汇总只在日期、秒数和次数都合法时迁移；
- 阶段 5 首版只有 v1，但必须保留迁移入口和测试夹具。

## 16. 测试架构

### 16.1 可注入边界

所有时间和副作用通过接口注入：

```ts
interface Clock {
  wallNowMs(): number;
  monotonicNowMs(): number;
}

interface SessionRepository { /* 原子命令，不暴露 DOM */ }
interface SoundPort { playNaturalCompletion(): Promise<void> }
interface ChannelPort { publish(event: StorageChanged): void }
```

测试不等待真实分钟，不把浏览器全局 fake timer 当作领域真值。可控 Clock 独立推进墙钟与单调时钟。

### 16.2 单元测试

必须覆盖：

- 1、20、60 分钟的开始、显示取整和自然归零；
- 暂停多次、继续多次、确认取消回运行／暂停来源；
- 0、1、59、60 秒提前结束；
- 自然完成固定记录计划秒数；
- reducer 对非法事件和陈旧会话 ID 的忽略；
- 墙钟前跳、后退、墙钟与单调时钟漂移；
- 本地日期跨午夜、月末、年末和夏令时日历序列；
- 7 天求和、15 天补零、最大柱高、全零基线；
- 日汇总溢出和坏字段验证；
- 15 日裁剪边界；
- 主题／声音字段级默认。

### 16.3 IndexedDB 集成测试

在真实浏览器 IndexedDB 中覆盖：

- 创建活动会话事务的双请求竞争；
- 同会话重复结算返回同一回执；
- 自然与提前结算并发只有一个日汇总增量；
- 事务在写回执前、中、后 abort 均不留下半条记录；
- 日汇总、回执、活动会话删除和 lastCompletion 同时提交；
- 损坏记录隔离与下一次维护修复；
- v1 初始化和未来迁移入口。

### 16.4 浏览器端恢复测试

| 编号 | 场景 | 断言 |
|---|---|---|
| R01 | 运行中刷新，未到期 | 同 ID、剩余按真实差减少、无追赶动画 |
| R02 | 暂停刷新 | 仍暂停、剩余不变 |
| R03 | 确认层刷新 | 仍确认、累计不增加、`resumeTo` 正确 |
| R04 | 后台／锁屏后未到期 | 回前台立即校正 |
| R05 | 后台期间到期 | 日汇总只加一次、完成页出现 |
| R06 | 关闭后未到期重开 | 恢复同一会话 |
| R07 | 关闭后过期重开 | 结算一次、不补播声音 |
| R08 | 同页墙钟前跳 | 使用单调差，不提前完成 |
| R09 | 跨重开墙钟倒退 | 丢弃不可信会话、不写记录 |
| R10 | 恢复数据缺字段 | 回首页、无猜测记录 |
| R11 | 完成页刷新 | 只读已有回执、不再次结算／播放 |
| R12 | 完成页后退 | 回首页，不回已结束进行页 |

### 16.5 竞争与多标签页

- 两个标签页同时点击开始，数据库仅有一个活动会话；
- 两标签页同时自然完成，只生成一份回执；
- 一页提前结束、另一页 tick 到 0，只有一个原因获胜且统计只增一次；
- 结算广播丢失时，另一页在 `visibilitychange` 后重读并收敛；
- 旧标签页在新会话开始后发旧 ID 命令，命令被拒绝；
- 完成音最多由一个活跃文档尝试一次。

### 16.6 体验与无障碍回归

- 只用键盘完成选择、开始、唤出控制、暂停、继续、确认、展开和返回；
- 模态初始焦点、圈定、Escape、遮罩取消和焦点归还；
- 控制淡出开始即不可点击且离开 Tab 顺序；
- 读屏不逐秒播报；图表每一天有文本等价；
- 200% 字号、360 px 手机、低于 620 px 高度和横竖屏旋转不改变领域状态；
- 减少动态模式下状态和 4 秒规则不变；
- 动画被取消、页面隐藏或样式加载失败仍可完成业务流程。

## 18. 架构决策记录

### ADR-01：不使用 UI 框架

三页和一个模态的规模不足以抵消框架运行时、状态复制和升级成本。原生 DOM 配合纯 reducer 已能满足可维护与可测试要求。若阶段 5 出现明确阻断，变更需证明不会产生第二状态源。

### ADR-02：IndexedDB 而不是 localStorage

单次结算需要把“检查回执、更新日汇总、写回执、删除活动会话”作为一个原子动作。localStorage 无法提供跨多个逻辑记录的事务；IndexedDB 可以把这些写入放在同一事务中。

### ADR-03：混合时钟而不是逐秒递减

单调时钟保证当前文档内不受墙钟调整影响，墙钟锚点允许刷新和关闭后恢复。回调只负责刷新显示，不负责累积真值。

### ADR-04：只保存日汇总

产品只展示 15 日按日统计。保存逐次历史会扩大数据范围并引入无用迁移和隐私成本。结算回执只服务幂等，不成为历史页面数据源。

### ADR-05：PWA 是外围适配器

Service Worker 生命周期不适合承担精确页面计时或结算。离线能力只缓存静态资源，业务恢复仍由页面和 IndexedDB 完成。
